# QiLing



## 基本功能

基于Flutter开发麒麟上位机控制App：
1. 硬件设备管控
   - 与 IJetty 服务端通信，实现 LED/LCD 大屏点屏拼接、接口卡连接关系配置、预置场景（播放 / 一键调用 / 定时切换）操控、RK 板卡 IP 等基础信息配置、瓶组控制等上位机操作；
2. 流媒体推流
   - 基于 FFmpeg_kit_flutter 实现文件推流（RTSP 协议），支持将本机视频文件封装推送至 RK 内网 MediaMTX 或云端 MediaMTX
   - 基于 RTMP+X264 编码实现直播推流（适配 USB 摄像头、监控摄像头等采集设备），非 RTMP 原生支持的 YUV+PCM 源数据先编码为 H.264+AAC 再通过 RTMP 推流
3. 流媒体拉流与预监
   - 通过 Media3 ExoPlayer（支持 RTMP/HLS/RTSP）拉流播放，实时展示 LED/LCD 大屏设备状态、预监板卡音视频流
   - 支持多用户并发访问 RK 板卡本地局域网流媒体资源池，直接拉取 RK 本地发布的 RTSP/RTMP 流完成移动端实时画面预监


## QiLin（麒麟）系统 - 核心问题梳理（更新版）
### 一、项目整体与架构
1. 麒麟Flutter App在整个系统中承担什么角色？与IJetty、RK板卡、MediaMTX、FPGA、大屏之间的数据流（控制流+媒体流）是怎样的？
2. 为什么选用Flutter开发控制端？流媒体播放模块是纯Flutter组件实现，还是通过通道调用Android原生Media3 ExoPlayer视图？

### 二、推流与编码（RTMP+X264/FFmpeg+RTSP）
1. 推流端区分场景说明：文件推流（RTSP）的推流端是App本机还是RK板卡？直播推流（RTMP+X264）的推流端是采集设备、App还是RK板卡？X264编码参数（I帧间隔、码率、分辨率、帧率）的实际配置值/策略是什么？
2. 协议/编码选型：
    - 为什么文件推流选RTSP、直播推流选RTMP？X264（H.264）编码的选型考量是什么？
    - 是否评估过H.265编码、WebRTC协议？未采用的核心原因（硬件适配/兼容性/延迟/成本）是什么？
3. 编解码硬件适配：嵌入式RK平台上，X264是软编码还是基于RK芯片的硬编码？是否使用RK硬件编解码模块（如RKMPP）处理H.264/AAC？
4. 网络适配策略：推流过程中遇到网络抖动、码率波动时，如何实现缓冲、主动丢帧、码率自适应？是否有针对局域网/公网不同场景的差异化策略？

### 三、拉流与播放（Media3 ExoPlayer）
1. 播放器选型：为什么选用Media3 ExoPlayer而非FFmpeg播放器、ijkplayer等？ExoPlayer支持RTMP协议是依赖media3-datasource-rtmp扩展实现吗？
2. 扩展原理：media3-datasource-rtmp的工作原理是什么？如何与ExoPlayer的数据源体系、播放管线协同？
3. 低延迟优化：ExoPlayer针对嵌入式/移动端预监场景做了哪些低延迟配置？RK嵌入式场景下实际播放延迟（端到端）大概多少毫秒？
4. 播放异常排查：播放出现卡顿、花屏、音画不同步时，定位问题的方法论（日志/工具/指标）是什么？对应的解决方案（如时间戳校准、解码缓冲调整）有哪些？
5. 协议容错策略：HLS和RTMP/RTSP流同时存在时，播放链路的切换逻辑、容错机制（如RTMP断流自动切HLS）、降级策略是什么？
6. 多流播放优化：多窗口/多画面同时播放多路流时，ExoPlayer实例的管理方式（复用/池化）、性能优化手段（如硬解共享、渲染层优化）有哪些？如何避免CPU/内存占用过高？

### 四、嵌入式与硬件适配（RK平台+FPGA+大屏）
1. 硬解码验证：RK平台上ExoPlayer的硬件解码是否生效？如何检测硬解状态？强制开启硬解的配置方式（代码/系统层面）是什么？
2. 高分辨率适配：大屏LED/LCD显示分辨率高，播放4K/1080P流时，如何避免卡顿、OOM、高CPU占用？是否用到RK/FPGA的硬件缩放、帧缓冲优化？
3. 预监板卡对接：预监板卡输出的流格式（RTSP/RTMP？编码格式？）是什么？如何将其接入到MediaMTX的RTMP/RTSP服务中供App预监？
4. 7×24小时播放保障：长时间播放场景下，如何做进程保活、防程序卡死、防黑屏、防音视频中断？是否有看门狗、心跳检测、自动重启机制？

### 五、异常与优化
1. 核心痛点：流媒体项目中最难解决的问题是什么（花屏/延迟/卡顿/断流/音画不同步）？对应的根因和核心解决方案是什么？
2. 断流重连：RTMP/RTSP流断开后，播放器自动重连机制如何实现（重试次数/间隔/触发条件）？是否区分“网络断连”和“服务端异常”？
3. 弱网缓冲策略：弱网环境下（尤其是公网链路），如何调整ExoPlayer的缓冲参数（预缓冲大小、缓冲阈值）？是否有动态调整逻辑？
4. 跨端通信：Flutter与原生Android ExoPlayer之间的通信（播放控制指令）、状态同步（播放进度/缓冲状态）、异常回调（卡顿/断流）如何设计？是否基于MethodChannel/EventChannel实现？

### 六、协议与格式深度
1. RTMP协议原理：RTMP推拉流的完整流程（握手、分块传输、元数据交互、音视频数据封装）是什么？关键环节的容错机制（如心跳包）如何？
2. X264帧结构：X264的I/B/P帧分别的作用？嵌入式大屏/监控场景下提高I帧频率的原因（如快速seek、断流恢复、同步）是什么？
3. 流状态检测：如何通过解析流数据（码率、时间戳、音视频轨道）判断流的状态（正常/无音频/无视频/码率异常/时间戳异常）？是否有自动化检测逻辑？
