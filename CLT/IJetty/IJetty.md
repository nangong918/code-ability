# IJetty


## 基本介绍

1. 依托 iJetty 搭建嵌入式端 HTTP 服务，接收 Web 前端下发的 JSON 控制指令；
2. 通过JNI/Native层进行数据编解码，将结构化 JSON 数据转换为 RK 芯片定制V 协议**二进制字节帧**，完成硬件指令下发。
3. 对接 RK 底层硬件通讯接口，监听芯片主动上报的 V 协议数据帧，经由 Native 层逆向解析后，通过 iJetty 内置WebSocket长连接，双向实时推送至前端。
4. 基于**AIDL**实现跨进程 IPC 通讯，完成与云端控制端 UberApp 的数据交互，构建云端远程操控链路。实现云端→Uber 跨进程→iJetty 上位机→RK 硬件的多级远程控制闭环，支撑设备远程调度与实时状态回传

3、项目核心分为哪几个模块？服务层、JNI协议层、硬件交互层、AIDL跨进程层分别如何解耦？

### 二、iJetty 服务核心（HTTP+WebSocket）

1、iJetty在Android嵌入式端如何部署、启动、托管？嵌入式设备无手机系统限制，如何保证服务常驻后台、防崩溃、防自停？

3、iJetty内置WebSocket长连接如何搭建？如何管理多客户端连接、区分终端、避免数据串发？

4、硬件端高频上报数据，WebSocket如何处理高吞吐、数据积压、实时性问题？有无消息队列、限流机制？

### 三、JNI 与 V协议编解码（核心难点）

1、Java层iJetty接收指令后，JNI调用采用静态还是动态方式？为什么选这种方案？

2、如何将前端JSON业务数据，编码转换为RK芯片定制V协议二进制字节帧？说明V协议帧结构（帧头、指令码、数据域、校验位、帧尾）？

4、RK硬件主动上报V协议帧，Native层如何反向回调Java层？JNI反向回调的线程安全问题如何解决？

5、JNI层长期运行，如何规避内存泄漏、缓冲区溢出、Native内存泄漏等嵌入式高频问题？

### 四、RK 底层硬件交互

RK芯片上的 为上位机提供Http服务的 App：Ijetty
前端下发Json到Ijetty，IJetty通过JNI将数据转化为RK芯片接受的V协议（字节帧）。
接收RK的主动上推V协议帧并通过WebSocket将消息推送给前端。
实现Web前端对上位机的调用服务。
并与UberApp进行AIDL的IPC通信，实现云上远程操控Uber然后Uber跨进程操控IJetty上位机。
