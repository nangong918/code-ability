# 操作系统

> 本篇整理操作系统核心概念（进程、线程、调度、同步），并结合 **Java / C++ / Kotlin 协程** 的工程实践，便于设计流媒体采集、编解码与网络发送的线程模型。可与 `../Media/Media.md` 中「线程池、后台 Service」等章节对照。

---

## 1. 操作系统视角：进程与线程

### 1.1 进程（Process）

- 资源拥有的基本单位：虚拟地址空间、打开的文件描述符、信号掩码等。  
- 创建开销较大；进程间通信（IPC）成本高于线程内通信。

### 1.2 线程（Thread）

- **CPU 调度的基本单位**（现代 OS）：同一进程内多线程共享地址空间，协作成本低。  
- 流媒体典型分工：**采集线程**、**编码线程或 JNI 回调线程**、**网络发送线程**、**UI 主线程**（仅更新界面）。

### 1.3 用户态协程（Kotlin Coroutine 等）

- **调度由运行时完成**，底层仍映射到线程池或少量线程；避免阻塞这些线程（尤其是 `Dispatchers.Main`）。  
- IO 密集（网络）可用挂起；CPU 密集（软编）应放到 **`Dispatchers.Default`** 或专用线程池。

---

## 2. 调度与并发问题

- **时间片轮转**：多线程分时占用 CPU。  
- **同步原语**：Mutex、信号量、条件变量（C++）、`synchronized`/Lock（Java）。  
- **常见问题**：数据竞争、死锁、虚假唤醒；**PacketQueue** 一类生产者消费者队列是典型的同步场景。

## 3. Java 线程池（`ThreadPoolExecutor`）

### 3.1 核心参数

| 参数 | 含义 |
|------|------|
| `corePoolSize` | 常驻核心线程数 |
| `maximumPoolSize` | 最大线程数 |
| `workQueue` | 等待队列（有界队列利于背压） |
| `RejectedExecutionHandler` | 队列满时的拒绝策略 |

### 3.2 流媒体侧建议（原则）

- **编码/网络**：CPU/阻塞 IO 混合时，使用**有界队列**，拒绝策略选 **丢弃最旧** 或 **调用者运行** 需权衡延迟。  
- **禁止**在单一无界队列里无限堆积原始 YUV，否则 OOM。

### 3.3 示例（节选）

```java
// 有界队列 + 丢弃最旧任务（示例：非关键后台任务）
ThreadPoolExecutor pool = new ThreadPoolExecutor(
        2, 4,
        60L, TimeUnit.SECONDS,
        new ArrayBlockingQueue<>(32),
        new ThreadPoolExecutor.DiscardOldestPolicy()
);
```

## 4. C++ 线程池（思路）

常用实现：`std::thread` + `std::queue` + `std::mutex` + `std::condition_variable`，或使用 **Intel TBB / folly::Executor** 等库。

要点：

- **任务队列有界**；  
- JNI 回调线程与 Java `attach` 规则要遵守（Android JNI）。

## 5. Kotlin 协程（摘录）

```kotlin
// IO：网络请求
lifecycleScope.launch(Dispatchers.IO) {
    val url = URL(hlsUrl)
    // ...
}

// CPU：大规模拷贝/软编前的预处理（仍建议专用池）
lifecycleScope.launch(Dispatchers.Default) {
    // heavy work
}
```

**注意**：协程不是魔法；CPU 密集任务仍会占用线程池中的线程。

## 6. Android 后台执行：Service vs Worker

| 方式 | 适用 |
|------|------|
| **前台 Service** | 长时间推流、定位等，系统限制后台启动 |
| **WorkManager** | 可延迟、可重试的后台任务（非实时推流首选） |
| **普通线程 + 生命周期绑定** | Activity 绑定的短任务 |

**长时间直播推流**：通常 **前台 Service + 独立线程/Native 发送线程**；与项目当前 Demo（Activity 内线程）不同，上线产品需单独设计。

## 7. Java `ThreadPoolExecutor` 拒绝策略一览

| 策略 | 行为 |
|------|------|
| `AbortPolicy`（默认） | 抛 `RejectedExecutionException` |
| `CallerRunsPolicy` | 调用者线程亲自执行，起到 **背压** |
| `DiscardPolicy` | 静默丢弃 |
| `DiscardOldestPolicy` | 丢弃队列中最旧任务 |

直播发送队列：**DiscardOldestPolicy** 有时优于无限堆积（换取实时性）。

## 8. C++ 线程池（极简自建骨架）

```cpp
#include <queue>
#include <thread>
#include <mutex>
#include <condition_variable>
#include <functional>

class ThreadPool {
public:
    explicit ThreadPool(size_t n) {
        for (size_t i = 0; i < n; ++i)
            workers.emplace_back([this] { workerLoop(); });
    }
    ~ThreadPool() {
        { std::scoped_lock lock(m); shutdown = true; }
        cv.notify_all();
        for (auto& t : workers) if (t.joinable()) t.join();
    }
    void enqueue(std::function<void()> f) {
        { std::scoped_lock lock(m); tasks.push(std::move(f)); }
        cv.notify_one();
    }
private:
    void workerLoop() {
        for (;;) {
            std::function<void()> f;
            { std::unique_lock lock(m);
              cv.wait(lock, [&]{ return shutdown || !tasks.empty(); });
              if (shutdown && tasks.empty()) return;
              f = std::move(tasks.front());
              tasks.pop();
            }
            f();
        }
    }
    std::vector<std::thread> workers;
    std::queue<std::function<void()>> tasks;
    std::mutex m;
    std::condition_variable cv;
    bool shutdown = false;
};
```

生产环境可替换为 **Intel TBB、folly::CPUThreadPoolExecutor** 等经过充分测试的实现。

## 9. Kotlin 协程与线程池关系

- `Dispatchers.Default` 背后为 **共享线程池**（CPU 核数相关）。  
- `withContext` 切换不会「创建魔法线程」，只是 **把续体挂到目标执行器**。  
- `Flow` + `flowOn` 可指定 **收集/处理** 所在调度器。  
- 与 **Java 线程池**可混用：`Executors.asCoroutineDispatcher()`。
