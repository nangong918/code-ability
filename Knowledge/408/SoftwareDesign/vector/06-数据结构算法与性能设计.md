# 06 数据结构算法与性能设计

## 1. 基于硬件架构做任务分析

`RK3588` 设备侧特点：

- 多核 CPU，适合并行 IO 和轻量推理前处理。
- GPU/NPU 可用于特定加速，但主链路主要依赖云端推理。
- 舵机控制实时性要求高，需保证控制队列稳定。

## 2. 时间优先场景结构与算法设计

- 语音触发链路：使用环形缓冲区保存最近 N 秒音频，触发后快速回溯。
- 动作调度：优先队列按 `deadline + priority` 排序。
- 延迟控制：采用令牌桶限流 + 超时快速失败。

## 3. 空间优先场景结构与算法设计

- 视频帧缓存采用有界队列，防止内存无限增长。
- 历史会话做摘要化存储，降低长上下文开销。
- 向量压缩与分层索引降低 Milvus 成本。

## 4. 缓存结构设计

- `L1` 设备内存缓存：最近会话上下文。
- `L2` Redis：跨服务共享状态与热点数据。
- `L3` 数据库/对象存储：长期持久化。

```mermaid
flowchart LR
  request[Request] --> l1[L1LocalCache]
  l1 -->|miss| l2[RedisCache]
  l2 -->|miss| db[PersistentStore]
  db --> l2
  l2 --> l1
```

## 5. 多线程数据结构选型

- 事件总线：`ConcurrentLinkedQueue` / 无锁 ring buffer
- 动作执行：`PriorityBlockingQueue`
- 状态快照：`CopyOnWrite` 适用于读多写少场景

## 6. 内存泄漏排查

- 设备端：JNI 全局引用和 native buffer 生命周期审计。
- 服务端：大对象缓存泄漏检测，异步任务引用链分析。
- 工具链：heap dump + allocation tracing + 周期性告警。

## 7. 海量数据分片索引设计

- 会话日志：按 `device_id + day` 分片。
- 向量检索：按用户维度分区 + HNSW/IVF 索引。
- 图谱：按用户域或业务域分图管理，避免超级节点热点。

## 8. 面试高频问答（本章）

- 问：时间优先与空间优先冲突怎么取舍？
  - 答：主交互链路优先时间，历史归档链路优先空间，并通过分层缓存平衡两者。
- 问：为什么动作队列用优先队列？
  - 答：可显式表达紧急停止等高优先级命令，保证安全相关动作抢占执行。
