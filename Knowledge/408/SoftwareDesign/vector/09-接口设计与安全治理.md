# 09 接口设计与安全治理

## 1. 接口设计原则与解耦

- 契约优先：先定义协议再实现，避免联调期频繁破坏。
- 版本化：`/api/v1`，兼容旧客户端。
- 幂等性：写操作使用幂等键，防止重复执行。
- 可观测：每次调用必须有 `trace_id` 与错误码。

## 2. 内部接口设计（服务间）

### 2.1 Orchestration -> Memory

- `POST /internal/memory/recall`
- `POST /internal/memory/persist`

### 2.2 Orchestration -> DeviceGateway

- `POST /internal/device/{deviceId}/command`
- `POST /internal/device/{deviceId}/face`

内部接口要求：

- mTLS
- 限流与熔断
- 超时默认值与重试策略标准化

## 3. 外部接口设计（Flutter/第三方）

示例接口：

```http
POST /api/v1/control/command
Authorization: Bearer <token>
Content-Type: application/json

{
  "deviceId": "d-10001",
  "commandType": "MOTION",
  "payload": {
    "actionId": "sit_down",
    "speed": "normal"
  },
  "requestId": "req-20260608-001"
}
```

响应示例：

```json
{
  "code": 0,
  "message": "accepted",
  "traceId": "trc-abc-001",
  "data": {
    "commandId": "cmd-7788",
    "status": "QUEUED"
  }
}
```

## 4. 接口安全性设计

- 身份认证：OAuth2/JWT，设备端短期凭证。
- 权限控制：用户、设备、运维分级 RBAC。
- 数据保护：敏感字段脱敏，日志中不落明文隐私数据。
- 攻击防护：签名校验、重放防护、速率限制、IP 黑白名单。

## 5. 错误码与重试规范

- 4xx：请求错误，不自动重试。
- 5xx：服务异常，可指数退避重试。
- 业务码：`DEVICE_OFFLINE`、`COMMAND_CONFLICT`、`MODEL_TIMEOUT`。

## 6. API 变更治理

- 变更评审：接口契约变更必须评审通过。
- 灰度发布：新版本按设备批次逐步放量。
- 废弃策略：至少两个版本兼容窗口。

## 7. 面试高频问答（本章）

- 问：接口幂等怎么做？
  - 答：客户端生成 requestId，服务端保存幂等键窗口，重复请求直接返回首次结果。
- 问：接口安全如何分层？
  - 答：入口鉴权、服务间 mTLS、数据加密、日志脱敏、审计追踪层层防护。
