## 1. 分层模型对照

### OSI 七层（概念模型）

| 层 | 名称 | 典型单元 | 示例 |
|----|------|-----------|------|
| 7 | 应用 | 应用数据 | HTTP、RTMP 消息、DNS |
| 6 | 表示 | 编码 | TLS 握手后的加密载荷 |
| 5 | 会话 | 会话 | SIP、RPC（概念层） |
| 4 | 传输 | 段 Segment | TCP、UDP |
| 3 | 网络 | 包 Packet | IP、ICMP |
| 2 | 数据链路 | 帧 Frame | 以太网帧、Wi‑Fi 帧 |
| 1 | 物理 | 比特 Bit | 电缆、射频 |

### TCP/IP 四层（工程常用）

```text
应用层（HTTP/RTMP/RTSP/DNS …）
传输层（TCP / UDP）
网际层（IP）
网络接口层（以太网 / Wi‑Fi …）
```

## 2. 与本项目流媒体相关的协议与承载

| 场景 | 典型传输 | 说明 |
|------|-----------|------|
| RTMP | **TCP**（默认 1935） | 字节流可靠有序；应用层协议自带 chunk/message |
| RTSP | **TCP 或 UDP** | 控制面常 TCP；媒体可走 RTP over UDP 或 TCP interleaved |
| HLS | **TCP（HTTP/HTTPS）** | `.m3u8` 与 `.ts`/`.m4s` 均为 HTTP 下载；天然 CDN 友好 |
| HTTP API | TCP | Spring Boot、MinIO、Nginx 反向代理 |

**要点**：乱序与丢包主要发生在 **UDP**；**TCP** 靠重传保证有序到达应用层，但会引入延迟抖动。

## 3. Wireshark 抓包入门

### 3.1 能抓到什么

抓包看到的是 **网卡可见的帧**：以太网头 → IP 头 → TCP/UDP 头 → **载荷**。  
应用层协议（RTMP 负载、HTTP body）在最后一层解析。

### 3.2 过滤器示例

```text
tcp.port == 1935          # RTMP 常用端口
tcp.port == 48888         # 示例 Spring Boot 端口
http.request.uri contains "m3u8"
udp.port == 554           # 有时 RTSP/RTP（视配置而定）
```

### 3.3 从物理层到应用层在 Wireshark 里的呈现（逻辑）

```text
Frame（捕获的一帧，含长度与时间戳）
 └─ Ethernet II（MAC）
      └─ IPv4 / IPv6
           └─ TCP / UDP
                └─ Payload（RTMP / HTTP / RTP …）
```

Wireshark 的 **Protocol Hierarchy** 统计各层占比；**Follow → TCP Stream** 可重组字节流查看 RTMP/HTTP。

## 4. RTMP / RTSP / HLS 在网络视角的差异（简述）

- **RTMP**：长连接 TCP，适合直播推流；服务端压力大时常配合 CDN/边缘转封装。  
- **RTSP**：会话描述 + 传输协商；媒体路径可能是 RTP/UDP，弱网可能花屏，可用 TCP interleaved。  
- **HLS**：多次短 HTTP 请求，切片缓存友好，易横向扩展（对象存储 + CDN）。

## 5. Wireshark 中一帧包的结构感（从以太网到应用层）

在 **Wireshark 主窗口** 选中一条记录，下方 **Packet Details** 树形展开，通常可见：

```text
Frame N: 捕获长度、时间戳
  └─ Ethernet II, Src: xx:xx..., Dst: yy:yy...
       └─ Internet Protocol Version 4, Src: a.b.c.d, Dst: e.f.g.h
            └─ Transmission Control Protocol, Src Port: 12345, Dst Port: 1935, Seq: …, Ack: …
                 └─ [ TCP Segment Len: m ]
                      └─ 若启用了 “Follow TCP Stream”，可看到 **连续字节流**（RTMP/HTTP 负载）
```

- **Frame**：抓包网卡上的一整段比特，带 **时间** 与 **长度**（可判断突发与重传）。  
- **Ethernet / Wi‑Fi**：二/一层寻址；Wi‑Fi 在 Wireshark 中可能显示 **802.11** 子层。  
- **IP**：分片、TTL、源目地址。  
- **TCP / UDP**：端口号、序列号/确认号（乱序、重传在 **TCP 分析** 中可见）。  
- **应用层**：需 **Dissector**；RTMP/HTTP 有对应解析；否则显示为 **Data** 或 **Raw**。

**判断「乱序」**：在 TCP 层看 **Out-of-Order** 专家信息；**UDP 乱序**需业务层或 RTP 序列号分析。

**判断当前是 UDP 还是 TCP**：查看 **Protocol** 列为 TCP 或 UDP，或展开传输层头。

## 6. 服务端「一对多」与瓶颈（概念公式）

单播场景下，每个观众一条（或多条）下行连接：

```text
总下行带宽 ≈ Σ(每个流的平均码率)
```

瓶颈常见为：**网卡出口带宽、CDN 边缘带宽、源站编码与磁盘 I/O、CPU 转封装**。十万级并发通常依赖 **CDN 分发**，源站只服务少量边缘节点而非终端。

## 7. 排查流媒体网络问题的顺序建议

1. **客户端**：是否解码错误、缓冲过长、时间戳异常  
2. **链路**：RTT、丢包、是否走错代理/VPN  
3. **服务端**：连接数、带宽、CPU、磁盘  
4. **抓包**：确认 TCP 重传、RTMP 是否中断、HTTP 切片是否 404  

更多与项目结合的排查见 `../Media/Media.md` 生产问题章节。
